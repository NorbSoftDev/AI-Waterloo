# Scourge of War: Waterloo — AI Source

This is the source code for the AI in **Scourge of War: Waterloo**: the battle AI that commands officers and units on the field, and the campaign AI. The game loads these as DLLs. Build your own copy to change how the AI fights, and share it as a mod.

The code is released under the MIT License (see [LICENSE](LICENSE)).

## What's here

| Folder | Builds | What it does |
|---|---|---|
| `SowAiInf` | `SowAiInf.dll` | Battle AI: officer orders, infantry, cavalry and artillery behaviour |
| `SowCampAI` | `SowCampAI.dll` | Campaign AI |
| `SowMod` | — | Shared headers that connect the AI to the game engine. Don't change these, because they must match the engine |

Open `AI-Waterloo.sln` in Visual Studio 2022 and build the `Release` configuration. The DLLs are built into `bin\Release`, and go in your mod's `Modules` folder. The [modding guide](docs/Modding.md) has the details.

## Latest release: Engine 1.022

### Changes for modders

- **Two new commands in the AI headers.** `SowMod\xunitdef.h` adds
  `eComCaptureKey` and `eComResetKeys`, used by the new Keyboard tab, at the
  end of the command list just before `eComMax`. All existing command numbers
  are unchanged, but `eComMax` is now 2 higher. The AI code uses `eComMax` to
  mean "no command", so rebuild AI mods with the updated `SowMod` headers to
  keep that value in step with the engine.
- **AI timer values now match the engine clock.** `TICSPERSEC` in
  `SowMod\xunitdef.h` was 60, but the engine (and `CXUtil::GetTime()`) counts
  360 ticks per second, so every AI timer built from `TICSPERSEC` or
  `TICSPERMIN` ran 6 times faster than written. It is now 360, and the shipped
  AI's timers have been rewritten to the times they really used, so the AI
  behaves exactly as before: division courier orders at most every 2.5
  minutes, help requests every 5 minutes, and brigade wheels every 2.5
  minutes. **If your AI mod uses `TICSPERSEC` or `TICSPERMIN`,** its timers
  will run 6 times slower once rebuilt with the new header; divide those
  values by 6 to keep the old timing.
- **AI tables are now data files.** The AI's orders, stances and division
  strategies used to be compiled into the AI DLL. They now load from three new
  files in `Logistics`: `orders.csv`, `stance.csv` and `playbook.csv`. The
  values are unchanged. To change AI behaviour, edit these files; you no
  longer need to rebuild the DLL. A mod can replace single rows, matched by
  order name, stance MaxVal or strategy Value, or add new ones. Each file
  starts with notes explaining every column. The game will not start if one
  of the files is missing. **AI DLL mods:** `SowInit` no longer supplies
  these tables and the DLL no longer needs `xtables.inl`. The engine fills
  `gTableDivStrat`, `gTableBrigStance` and `gTableTacOrders` before it calls
  `SowInit`. Existing AI DLLs still work, but tables compiled into a DLL are
  now ignored. If your AI mod changed its own `xtables.inl`, move those
  changes into the three CSV files.

### Earlier changes for modders

#### Engine 1.021

- **More AI save slots for modders.** Each officer now has 30 integer slots for
  AI mods (`TicksForOffSDK`), up from 10. They are stored in the saved game.
  Slots now start at 0 on every officer; before, they could hold random values
  until a game had been saved and reloaded. Existing AI mods work unchanged.
  Saves from earlier versions load with the new slots set to 0. Saved games
  made with this version should not be loaded in earlier versions.

#### Engine 1.020

- The ground bump uses a new terrain shader, `Shaders\TerrainSplatter_sm3.fx`,
  alongside the existing `TerrainSplatter.fx`, which remains the Shader Model 2.0
  version and fallback. Post-processing uses `Shaders\postprocess.fx`. If either
  new file is missing, the game quietly falls back to the original rendering.

#### Engine 1.019

- **Drill slot maps now tolerate padding spaces.** A slot-map cell holding only
  spaces looks empty in a spreadsheet, but the loader did not treat it as empty:
  it read the cell as slot 0 and wrote that man's sprite, facing, subtype and
  lock one element before the start of the formation's arrays, corrupting
  neighbouring data. Leading spaces also hid a cell's `(...)` parameters, so a
  cell written `  (0-0-6)5` lost both its parameters and its slot number. Cells
  are now trimmed before they are read, so spacing in `drills.csv` no longer
  changes how a formation loads.
